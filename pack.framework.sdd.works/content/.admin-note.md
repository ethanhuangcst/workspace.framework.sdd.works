## Instructions page tabs — `content/.instructions-tabs.json`

The public instructions page (`/` and `/instructions`) reads tab order and tab types from this file after Admin → Sync. The bundled copy in the web app repo (`src/content/.instructions-tabs.json`) is used only when the sync cache file is missing or invalid.

### File location

- Pack repo path: `content/.instructions-tabs.json`
- After sync: `{unpacked}/content/.instructions-tabs.json` (same tree as `content/features/`)

### Top-level shape

- `version`: number, use `1` for the current schema.
- `tabs`: array of tab objects. **Display order on the page is array order.**

### Tab types

| type | Meaning |
| --- | --- |
| `code` | Built-in React panel in the portal. The `id` must match an allowlisted panel in the app (today: `setup` only). Operators cannot add new code tabs without a portal release. |
| `content` | Markdown loaded from the synced pack (then locale fallback). The tab body is not React code in the pack. |

### Fields on every tab row

| Field | Required | Notes |
| --- | --- | --- |
| `type` | yes | `code` or `content` |
| `id` | yes | Stable slug; unique in the file |
| `labelKey` | yes | i18n key for the tab label (for example `admin.guide.tab_features`) |
| `queryParam` | yes | Value for `?tab=` on `/` and `/instructions`; unique in the file |
| `panelTestId` | yes | `data-testid` on the tab panel (for example `panel-features`) |

### `content` tabs only

| Field | Required | Notes |
| --- | --- | --- |
| `paths` | yes | Map locale → relative path under the unpack root. Must include `en`. Optional `zh-Hans` and `zh-Hant`; missing locales fall back to `en` inside the same source (cache or bundled), same as Features. |

Path rules:

- Relative path only; no `..`, no leading `/`.
- Prefer paths under `content/` (portal content paths ADR-071 in product specs).
- Each path must point at a markdown file that exists in the pack after sync.

### `code` tabs only

- Include a row with `id` `setup` for the MCP install panel (copy prompt, manual `mcp.json`, agents, tools, Get secret).
- No extra fields beyond the common row fields.

### Runtime behavior (for operators)

- **Default tab:** When the URL has no `?tab=`, the page always opens **Setup** (`queryParam` `setup`), even if another tab is listed first in JSON.
- **Config source:** Valid file in the sync cache wins. If the cache file is missing or fails validation, the portal uses **only** the bundled `src/content/.instructions-tabs.json` (no partial merge).
- **Reorder tabs:** Edit this file in the pack repo, commit, then Admin → Sync. No portal redeploy is required for order or content-tab path changes.
- **Add a content tab:** Add a `content` row, add markdown files at the paths you name, sync, and add the `labelKey` to all three locale catalogs in the portal repo if it is a new key.

### Example (default product tabs)

```json
{
  "version": 1,
  "tabs": [
    {
      "type": "code",
      "id": "setup",
      "labelKey": "admin.guide.tab_setup",
      "queryParam": "setup",
      "panelTestId": "panel-setup"
    },
    {
      "type": "content",
      "id": "features",
      "labelKey": "admin.guide.tab_features",
      "queryParam": "features",
      "panelTestId": "panel-features",
      "paths": {
        "en": "content/features/features.en.md",
        "zh-Hans": "content/features/features.zh-Hans.md",
        "zh-Hant": "content/features/features.zh-Hant.md"
      }
    },
    {
      "type": "content",
      "id": "scrum-in-sdd",
      "labelKey": "admin.guide.tab_scrum",
      "queryParam": "scrum-in-sdd",
      "panelTestId": "panel-scrum",
      "paths": {
        "en": "content/scrum-in-sdd/scrum-in-sdd.en.md",
        "zh-Hans": "content/scrum-in-sdd/scrum-in-sdd.zh-Hans.md",
        "zh-Hant": "content/scrum-in-sdd/scrum-in-sdd.zh-Hant.md"
      }
    }
  ]
}
```
