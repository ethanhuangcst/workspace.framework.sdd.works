# Notes to the admin

Read this note before you update framework.sdd.works

## **How to update framework.sdd.works artifacts**

- Copy the newest framework artifacts to local framework workspace folder
- Sync with Git repo (default: "[https://github.com/ethanhuangcst/framework.sdd.works.git](https://github.com/ethanhuangcst/framework.sdd.works.git)")
- sdd.works web app will auto sync every 30 minutes, or manual sync on Admin portal - Framework - Sync with git repository

## **How to customize content tabs on instructions page**

### 1. Prepare content

- Put markdown under `content/<topic>/` (for example `content/features/`, `content/scrum-in-sdd/`).
- One file per locale: `<topic>.en.md`, `<topic>.zh-Hans.md`, `<topic>.zh-Hant.md`.
- English is required. Other locales fall back to English when a file is missing.
- **Scrum in SDD (human, this folder)** files under `content/scrum-in-sdd/` are for the portal. They include an Index, must not link to product-only paths, and must read standalone. English order: Part I–III, then **Appendix: Short summary of the 2020 Scrum Guide**. After part, appendix, or h2 title changes, run `node scripts/rebuild-scrum-in-sdd-en.mjs --index-only` in the **framework.sdd.works** product repo. Index lists h1 and h2 only ([ADR-109](https://github.com/ethanhuangcst/framework.sdd.works/blob/main/specs/adr/ADR-109-content-tab-heading-anchors.md) in the product repo).
- **Scrum in SDD (AI-read)** lives beside `constants.json` under `templates/` as `pack-scrum-in-sdd.md`, `sdd-scrum-practices.md`, and `coach-knowledge.md` (EN only; not copied into a project workspace). No Index on the guide; install-safe links only. Keep semantics aligned with human seeds ([ADR-125](https://github.com/ethanhuangcst/framework.sdd.works/blob/main/specs/adr/ADR-125-dual-audience-scrum-guide-and-guide-editor-skill.md), [ADR-126](https://github.com/ethanhuangcst/framework.sdd.works/blob/main/specs/adr/ADR-126-ai-read-pack-templates-and-pack-scrum-in-sdd-filename.md)). Use `.cursor/skills/sdd-guide-editor/` in the product repo when editing both variants.
- Keep every list **tight** (no blank line between a bullet and its continuation) so Cursor preview renders the full file.

### 2. Configure JSON

- Edit `content/.instructions-tabs.json` in this repo.
- Tab order is the `tabs` array. Tab titles are `labels` per locale, not portal message keys.
- Types: `code` (built-in panel), `content` (`paths` from step 1), `embedded_external_page` (`urls` per locale), **`internal_page_folder`** (`rootPath` plus per-folder `.index.json`; contract [ADR-124](https://github.com/ethanhuangcst/framework.sdd.works/blob/main/specs/adr/ADR-124-internal-page-folder-index-json.md) in the product repo).

### Internal page folder (spike)

- Put a folder tree under `content/<tree>/` (example: `content/knowledge/`).
- Each folder that appears in the UI ships **`.index.json`** (`version`, optional `labels`, `entries[]`).
- **List headings:** Every folder listing shows one panel **`h2`** from that folder’s **`.index.json`** **`labels`** (tab root and every subfolder). Put **`labels`** on the root index and on each subfolder index. Article view (`doc=`) does not show the folder **`h2`**.
- **`file`** entries use **`paths`** like a `content` tab (locale → `.md` relative to that folder).
- **`folder`** entries use **`path`** to a subfolder (relative to the current folder).
- Required **`open`** on each **`file`** row: **`same_tab`** (article in the guide panel, Back button) or **`new_tab`** (listing stays; row uses external-link UI; article in a new browser tab). Folders always drill in on the same tab.
- Mirror the tree to `src/content/` in the product repo when you want bundled fallback before Git sync.

```json
{
  "version": 1,
  "tabs": [
    {
      "type": "code",
      "id": "setup",
      "labels": { "en": "Setup", "zh-Hans": "安装", "zh-Hant": "安裝" },
      "queryParam": "setup",
      "panelTestId": "panel-setup"
    },
    {
      "type": "content",
      "id": "features",
      "labels": { "en": "Features", "zh-Hans": "功能", "zh-Hant": "功能" },
      "queryParam": "features",
      "panelTestId": "panel-features",
      "paths": {
        "en": "content/features/features.en.md",
        "zh-Hans": "content/features/features.zh-Hans.md",
        "zh-Hant": "content/features/features.zh-Hant.md"
      }
    },
    {
      "type": "embedded_external_page",
      "id": "learn-scrum-in-sdd",
      "labels": {
        "en": "Learn Scrum in SDD",
        "zh-Hans": "学习 Scrum in SDD",
        "zh-Hant": "學習 Scrum in SDD"
      },
      "queryParam": "learn-scrum-in-sdd",
      "panelTestId": "panel-learn-scrum",
      "urls": {
        "en": "https://sdd.works/en/learn-embedded/",
        "zh-Hans": "https://sdd.works/en/learn-embedded/",
        "zh-Hant": "https://sdd.works/en/learn-embedded/"
      }
    }
  ]
}
```

### 3. Optional: sync to product repo

- Copy the same markdown and `content/.instructions-tabs.json` to `src/content/` in the framework.sdd.works product repo.
- If you skip this step, Admin → Sync still serves tabs from this pack after push.
- The portal uses the bundled `src/content/` copy only when sync cache is missing or invalid (local dev, first boot, bad cache). Then tabs and markdown can stay stale until you sync `src/content/` or fix cache.

### 4. Commit and push

- Commit in this pack repo and push to Git.
- On the portal: Admin → Framework → Sync with git repository.
- In the product repo, run `npm run check:pack-seeds` before you push mirrored seeds.
